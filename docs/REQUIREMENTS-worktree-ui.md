# dsh-worktree 需求说明

## 一、侧边栏会话图标

每个会话行前面要有一个图标，一眼看出这个会话在哪儿干活。

- 会话在主仓库里 → 分支图标
- 会话在某个工作树里 → 工作树图标，并能看出是哪个工作树

图标只看会话**实际所在的目录**，不看它显示在哪个分组下面。侧边栏的分组是按 workspace 分的，不是按工作树分的——同一个分组里可以既有主仓库的会话，也有工作树的会话，所以分组名和图标没有关系。

鼠标悬停时显示完整信息：工作树名 + 分支名。

---

## 二、新建会话时选目录和分支

从侧边栏 `+` 号新建会话时：

- 默认工作目录 = 主工作区
- 默认分支 = 主工作区当前分支
- 可以把分支换成任意一个工作树的分支；换过去之后，**工作目录跟着变成那个工作树的目录**

规则细节：

- 分支显示成「工作树名/分支名」，例如 `wt-29db/test3`。这个名字本身就唯一，所以只需要选分支，不需要再单独选目录。
- 不需要在点 `+` 号之前弹选择器。会话建出来之后，在输入框旁边选就行，效果一样。
- 换工作树等于换目录，跟旧目录有没有未提交改动无关，不拦。

---

## 三、通过「永久工作树」新建会话

- 默认工作目录 = 那个工作树的目录
- 默认分支 = 那个工作树的分支
- 同样可以再切换到别的分支或工作树

---

## 四、已经存在的会话

- 工作目录**不能改**
- 只能切换分支

理由：工作目录是会话的身份，改了上下文就乱了。

---

## 五、切分支时要处理的情况

1. **老会话的分支列表按「分支出身」划分**
   每个分支都有一个**出生地**（在哪个检出里创建的）：在主仓库里创建的分支（如从 main 上建出 a、b、c）属于主仓库的家；在某个 worktree 里创建的分支（如从它的 d 上建出 e、f、g）属于那个 worktree 的家；worktree 自己的分支 d 也属于那个 worktree。
   老会话在主仓库 → 显示 main + a、b、c（主仓库家）。老会话在 worktree → 显示 d + e、f、g（这个 worktree 家）。**互相看不到对方的分支。**主干分支（如 main）是主仓库家的根，主仓库会话**永远显示**它——切到子分支后也要能切回来。
   家里被别的检出占用的分支不出现（Git 不允许同一分支两处检出）。仅当点击瞬间分支恰好被占用（竞态）时，提示「无法切换到该分支，它已属于工作树 X」，并提供「去那个工作树」的操作。**不要**把当前会话搬过去。
   Git 本身不记录分派出身，**只有插件创建的分支才记账**（创建分支、创建工作树、远程跟踪创建三条路径，记录存于 pool 目录 `.branches.json`）。用户自行创建的分支没有记录，无法判断属于哪个家，**一律不显示**——唯一例外是会话自己当前检出的分支（身份行，无记录也显示）。

2. **当前目录有未提交改动**
   提示用户，让他确认。这是已经有功能，保持不变。

3. **面板措辞只有「切换」**
   分支列表从头到尾都是切换语义：新会话、老会话点的都是「切换到某分支」，不出现「迁移」「检出」这些词。
   「检出」的唯一入口是底部的**创建工作树**按钮——把一个分支检出成它自己的工作树，只能从这里走。老会话想换分支走底部**创建分支**（新建并切换）。

---

## 六、一句话总结

**选分支就是切分支，不是搬会话。**

只有新建会话时，选别的工作树的分支才会连带换目录。

---

## 七、怎么判断做对了

| 操作 | 正确表现 | 错误表现 |
| --- | --- | --- |
| 新会话里点一个别的工作树的分支 | 会话目录和分支一起变过去，提示「已切换到 X」 | 只变了分支、目录没变；或出现「迁移」字样 |
| 老会话在主仓库看分支列表 | main（主干，恒显示） + 插件在主仓库创建的分支（a、b、c） | 显示 worktree 家的分支（d、e、f、g）或无记录的用户自建分支；或切到子分支后 main 消失 |
| 老会话在 worktree 看分支列表 | 自己的分支 d + 插件在这个 worktree 创建的分支（e、f、g） | 显示主仓库家的分支、其他 worktree 家的分支或无记录的用户自建分支 |
| 老会话点家内的分支 | 就地切换分支，目录不变 | — |
| 当前目录有改动时切分支 | 弹确认，问要不要继续 | 直接切走 |
| 想把某个分支检出成独立工作树 | 只有底部「创建工作树」一个入口 | 分支列表里出现任何「检出」入口或字样 |
| 看侧边栏 | 在哪个目录干活就显示对应图标 | 按分组名猜图标 |
